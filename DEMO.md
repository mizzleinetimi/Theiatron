# Theiatron live-demo runbook

## What the audience sees

The primary demo performs fresh inference on the selected video:

1. YOLO detects vehicles and ByteTrack builds their trajectories.
2. The system clusters moving tracks into traffic approaches and places count
   lines automatically.
3. A review screen shows the learned approaches and calibration quality.
4. The video rewinds and a new inference pass analyzes the complete clip. An
   optional `--evaluation-scope unseen` mode instead continues beyond the
   calibration segment.
5. Each newly counted arrival is sent to adaptive and equal-cycle fixed-timer
   point-queue simulations.
6. The dashboard shows modeled queueing, average wait, vehicles waiting now,
   and cumulative vehicle-seconds saved.

Recorded vehicles cannot react to a simulated light. Detection and arrival
measurement are real; signal response and queue discharge are simulated.

## Before the presentation

Use a static elevated shot of one intersection. Prefer 180 seconds or more of
daylight footage with vehicles entering from at least three approaches. Avoid
cuts, moving cameras, dashcams, highways, and mostly empty clips.

Run the full test once:

```bash
bash scripts/live_demo.sh videos/intersection.mp4
```

The stage launcher uses up to 180 seconds for calibration and 180 seconds for a
fresh full-video evaluation. The evaluation automatically shortens to the
available footage.
Artifacts are written to `out/live-YYYYMMDD-HHMMSS/`.

For a shorter rehearsal:

```bash
THEIATRON_OBSERVE=180 THEIATRON_DURATION=30 \
  bash scripts/live_demo.sh videos/intersection.mp4
```

## Stage checklist

- Plug the laptop into power and disable sleep.
- Close GPU/CPU-heavy applications.
- Disconnect from the internet and run the preflight once.
- Confirm `yolo26n.pt` and the source video are present.
- Confirm the output disk has at least 2 GB free.
- Use the motion road-mask backend; it does not download another model.
- Keep the latest `annotated.mp4`, `calibration.png`, and `report.md` open as
  fallbacks.
- Press `q` to stop the live evaluation and keep the results collected so far.

## Presenter wording

> The system is processing this video now. It learned the approaches from
> vehicle motion, and every crossing you see becomes the same arrival in two
> simulations: an equal-cycle timer and Theiatron's adaptive controller.

When presenting a result, qualify it as specific to the current footage:

> On this detected demand stream, Theiatron produced X% lower modeled average
> wait than an equal 30-second fixed timer.

Do not describe the modeled waits as measured roadside delay or claim that the
prototype is ready to drive physical signal lamps.

## Failure handling

If calibration reports low confidence, use a longer clip with a static elevated
view and more cross-street traffic. The application rejects incomplete phase
layouts and collapsed count lines rather than continuing with misleading data.

If fewer than 10 arrivals cross the learned lines, the report is marked
inconclusive and the dashboard withholds the percentage headline.

If the live window or projector fails, play the most recent run's
`annotated.mp4`. Its detections, arrivals, controller states, and metrics were
generated by the same live pipeline.
